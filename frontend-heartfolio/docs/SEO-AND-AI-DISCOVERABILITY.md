# SEO & AI / Machine Discoverability

Everything here was read from the source. Nothing is aspirational: if a
mechanism is not implemented, this document says so.

## 1. Metadata

(`lib/site-config.ts`); helpers live in `lib/seo.ts`.

## 2. Sitemap — implemented

`app/sitemap.ts` emits **every public route once per locale** with an
`alternates.languages` block:

| Path | Priority | Change frequency |
|---|---|---|
| `` (home) | 1.0 | weekly |
| `/products` | 0.9 | weekly |
| `/products/{slug}` × all registry products | 0.8 | monthly |
| `/contact` | 0.5 | yearly |
| `/terms`, `/privacy`, `/refunds` | 0.3 | yearly |

Product URLs come from the **frontend registry**, so all four products
appear — including the two waitlist products, which have real marketing
pages. Customer-flow routes are correctly absent.

## 4. Structured data (JSON-LD) — implemented on three pages

| Page | Schema types | Notable fields |
|---|---|---|
| Home | `WebSite`, `Organization`, `FAQPage` (`Question`/`Answer`), `Brand`, `ContactPoint` | Site identity, brand, FAQ from `messages` |
| `/products` | `CollectionPage`, `ItemList` → `ListItem` → `Product` | Each product with name, description, url |
| `/products/[slug]` | `Product`, `AggregateOffer` / `Offer`, `BreadcrumbList` | **Prices from Django at request time** |

**Prices in structured data are dynamic and real.** The product page renders
per request and its offers reflect the live catalog — verified by observing
`"price":"8.00"` etc. change with the database. Availability is represented
through the offers that exist: an unavailable pack is simply absent.

Localized: names, descriptions and FAQ text come from the active locale's
messages, so `/fr` and `/ar` emit French and Arabic structured data.

**Not implemented:** `Review`/`AggregateRating` (no reviews exist),
`VideoObject`, `HowTo`, `LocalBusiness`. Correctly so — inventing them would
be fabricating signals.

## 6. AI / machine discoverability

### A. What is actually implemented

- **Crawlable, server-rendered public product pages.** Marketing and product
  pages render on the server, so content is present in the initial HTML
  rather than assembled by JavaScript.
- **Descriptive URLs** — `/en/products/where-we-met`, not opaque ids.
- **Schema.org `Product` + `Offer`** with live prices and currency.
- **`Organization` + `Brand` + `ContactPoint`** — an explicit entity for the
  brand, not just pages.
- **`FAQPage`** with real question/answer pairs.
- **`BreadcrumbList`** expressing site hierarchy.
- **`ItemList`** on the collection page relating products to the brand.
- **hreflang with `x-default`** across en/fr/ar.
- **Per-page canonicals**, so the three locale versions aren't duplicates.
- **A complete sitemap** with localized alternates.
- **Open Graph and generated OG images** for link previews.
- **Semantic HTML** — `main`, `section`, `h1`/`h2`/`h3` hierarchy, `nav`,
  `footer`, descriptive `alt` where images exist.
- **Long-form topical copy** per product (story, FAQ, offering
  descriptions) in three languages.
- **Internal linking** — home → collection → product → create.

### B. How each helps machine understanding

- *Server-rendered content* means retrieval systems and crawlers that do not
  execute JavaScript still see the full page.
- *Schema.org Product/Offer* lets extraction systems read what is sold and
  what it costs without inferring it from prose.
- *Organization/Brand* gives knowledge-extraction systems a stable entity to
  attach products, contact details and site identity to.
- *FAQPage* supplies question-shaped content that maps directly onto the
  way people phrase requests to assistants.
- *Canonicals + hreflang* prevent three language versions from diluting or
  competing with each other, and tell a system which version suits a user.
- *Sitemap* gives crawlers a complete, authoritative URL list rather than
  relying on link discovery.
- *Descriptive URLs and headings* provide strong lexical signals for
  retrieval and chunking.

### C. What is NOT guaranteed — read this

**No website can force ChatGPT, Gemini, Claude, Perplexity, Google AI
Overviews or any other AI system to recommend it.** These systems choose
what to surface using their own models, indexes, licensing arrangements and
ranking. Nothing in this codebase changes that, and any claim otherwise
would be false.

What the work above *does* achieve is making Heartfolio:

- crawlable — content reachable without executing JavaScript
- understandable — products, prices and brand stated in machine-readable form
- semantically clear — one page per intent, descriptive URLs and headings
- consistent — the same facts in metadata, structured data and visible copy
- retrievable — complete sitemap, canonical URLs, no duplicate dilution
- associable — topical copy connecting products to real gift occasions

That is the honest ceiling: eligibility and clarity, not guaranteed
recommendation.
